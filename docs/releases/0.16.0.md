# Teachouse 0.16.0

## FilesStreaming

**Files you import stay on your devices.** Teachouse no longer copies imported files to its servers. When you view a file, make a preview from it or download it in the console, Teachouse asks one of your devices that holds it for the file and passes it straight through to your browser without keeping it. Files you upload yourself in the console are still stored by Teachouse and are always available.

- **The copies 0.15.0 made are deleted.** Migration 0099 deletes every stored copy of an imported file. It deletes the database row that holds each copy's encryption key, so the encrypted object left in storage can never be opened again, and the store's own lifecycle removes it later. Uploads, thumbnails, avatars and anything an import still names are untouched. A copy no longer counts towards your plan's storage.
- **View, Preview and Download work through your device.** They need one of your devices that holds the file to be on, with the Teachouse app open. PDFs still open a few pages at a time (the browser asks for byte ranges, and Teachouse asks the device for just those bytes), so the first pages draw before the rest arrives. Large files are fetched from the device in parts of 32 MB.
- **When the device is off**, the console says "Your file is on <device>, which is offline. Open the Teachouse app there." and has an **Explain** link. A device counts as online for this while its app has checked with Teachouse in the last minute.
- **Your devices' files**: the **Where** column shows only device names, each with an online dot. Files you uploaded show **Uploaded**. The Teachouse/both states are gone.
- **Android** shows a notification, "Teachouse is sharing your files", while it can pass files on, including with the screen off. The phone stops sharing 10 minutes after you last used the app or it last passed on a file, which saves battery. After that, open the app to share again. Battery savers on some phones can stop it sooner.
- **The desktop app** answers file requests while it is running. It no longer copies files to Teachouse in the background.
- **Safety.** Each request to a device carries a single-use permission signed by Teachouse. It names the device, the file and the exact bytes, and expires after two minutes. The device refuses any request that doesn't match. Your marketplace logins and Teachouse sign-in never leave the device. Teachouse keeps only the request (which file, which bytes) until it is answered, and never the bytes themselves.

Why: `docs/notes/design/research/2026-09-29-file-custody.md`.

Routes: removed `GET /v1/library/missing` and `PUT /v1/library/files/{hash}`. Added `GET /v1/devices/{device}/streams` (the device's long poll) and `POST /v1/devices/{device}/streams/{stream}` (the device's answer). `GET /v1/products/{p}/files/{f}/content` and `GET /v1/library/files/{hash}/content` pass imported files through from a device and take `?probe=1`. New error codes: `device_offline` (409, `detail.device`) and `streaming_unavailable` (503). `FileView.server_copy` is replaced by `custody` (`uploaded`, or `devices` with holders), and `LibraryFileView.server_copy` by `uploaded`.

Migration: `0099_device_streams.sql` adds `device.stream_polled_at` and the `device_stream` table (request metadata only, row-level security like every tenant table) and deletes the server copies.

Deploy: tam-server runs as two replicas. A device's answer can reach either one, so each pod must know the address the other can reach it on. Add `TAM_POD_IP` from `status.podIP` (downward API) to the tam-server container, and add `--broker-advertise $(TAM_POD_IP):<serverPort>` to its args. Without that flag, an answer that lands on the other pod is refused and the viewer shows the device as offline. The pods must be able to reach each other on the server port, which the cluster network already allows. The broker signs requests with the entitlement key (`--entitlement-key-path`, already configured); a deployment without it answers `streaming_unavailable`. Ship the desktop and Android 0.16.0 builds with the server. Apps older than 0.16.0 don't answer file requests, so their files show as offline until they update.
