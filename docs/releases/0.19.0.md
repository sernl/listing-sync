# Teachouse 0.19.0

## Web

- **The console has its own address.** Teachouse is now `https://dash.teachouse.io`; `teachouse.io` is the marketing site. Every "Log in", "Start free", "Choose a plan" and FAQ link on the site goes to `dash.teachouse.io` (`consoleUrl` in `apps/landing/src/site.js`; set `PUBLIC_CONSOLE_URL` at build time to point a local landing build at a local console). The site's own banner, plans and analytics stay on `teachouse.io`.
- **The desktop app is sent to the console's host.** A desktop window that lands on the marketing site is moved to `https://dash.teachouse.io/app`. `/app-redirect.js` is now generated at build time so it carries the console's address.
- **The sign-in and sign-up pages link the terms and privacy policy on `teachouse.io`.** They open in a new tab, or in the computer's browser from the desktop app, so a half-filled form is not lost. Console links to the marketing site are built from `MARKETING_URL` in `web/src/lib/site.ts`.
- **Search engines skip the console.** Every console page carries `<meta name="robots" content="noindex">`. The marketing site's `robots.txt` now covers only its own host: it blocks `/v1/`, `/api/`, `/ingest/`, `/downloads/` and the maintenance preview, and no longer lists console routes. The flake check `served-artefacts` enforces this. The console host answers its own `robots.txt`.
- **The search listing's app address is the console.** The `SoftwareApplication` structured data has `url` `https://dash.teachouse.io/` and `installUrl` `https://dash.teachouse.io/signup`. The plan offers still point at `teachouse.io/pricing/`.
- **Passkeys keep working across the move.** When `TAM_AUTH_PASSKEY_RP_ID` is unset, tam-auth binds passkeys to the base URL's registrable domain (its last two labels). For `dash.teachouse.io` that is `teachouse.io`, which is valid on every subdomain. A deployment under a two-label public suffix such as `co.nz` must set the variable itself. `TAM_AUTH_BASE_URL` and `TAM_AUTH_TRUSTED_ORIGINS` remain tam-auth's only origin inputs, and its cookies stay host-only.
- **The browser extension asks for `https://dash.teachouse.io/*`** in place of `https://teachouse.io/*`.
- Design notes, the landing README and the `just guides-images` example now use the new host. The guides contain no absolute console URLs, so they did not change.

Deploy: set `TAM_AUTH_BASE_URL=https://dash.teachouse.io` (the NixOS module derives it from `consoleHost`) and leave `TAM_AUTH_PASSKEY_RP_ID` unset. Existing passkeys were registered against `teachouse.io` and keep working. Republish the extension with the new host permission.

## Desktop

- **The app opens the console on `dash.teachouse.io`.** The window loads `https://dash.teachouse.io/resources` instead of `https://teachouse.io/resources`, and checks in, registers, imports and returns from marketplace sign-ins against the same host. `control_plane::CONSOLE_ORIGIN` (renamed from `DEFAULT_BASE_URL`) is the one Rust constant every path and test reads; `TAM_CONTROL_PLANE` still overrides it for development.
- **Commands are granted to the new origin only.** `capabilities/console.json` and `capabilities/opener.json` name `https://dash.teachouse.io` in `remote.urls`, and the `connect-src` in `tauri.conf.json` names it as the one remote origin the bundled pages may reach. A new unit test (`the_committed_origin_lists_name_the_console_origin`) reads all three files and fails if any of them names another origin, so a later move cannot leave the console refusing every command.
- **Downloads and updates are unchanged.** The updater still reads CrabNebula, and the installers and `downloads.json` stay at `https://teachouse.io/downloads/…`. The app has no links to marketing pages; anything it opens in the browser goes through the opener, which still allows any `https://` address.
- **Upgrading.** A desktop build older than 0.19.0 still loads `https://teachouse.io/resources`, which the server now redirects to `dash.teachouse.io`. On that host its command grants no longer match, so the console says the page is not one the app accepts commands from until the app updates. Ship the 0.19.0 desktop build together with the server release. The Android manifest names no web host, so nothing changes there.
