# Teachouse 0.19.0

## Server

- **Two hosts.** `teachouse.io` is the public site and `dash.teachouse.io` is the console. tam-server takes `--landing-host teachouse.io --console-host dash.teachouse.io`, given together or not at all; one alone stops start-up with "--landing-host and --console-host are given together or not at all". Without them every host gets one origin, as before, which is what development and the tests run.
- **What stays on teachouse.io.** The landing pages and their files, `/downloads/*`, `/v1/site`, `/v1/plans`, `/ingest/*` (the landing's own analytics proxy), `/healthz`, `/robots.txt` and `/sitemap.xml`.
- **What moves to dash.** Every other path on teachouse.io answers `301` to the same path and query on `https://dash.teachouse.io`: the console's pages, `/_app/*`, `/api/auth/*` and every other `/v1/*` route. Old links and guides keep working.
- **What moves back.** On dash, `/pricing`, `/terms`, `/privacy`, `/maintenance` and `/sitemap.xml` answer `301` to teachouse.io. `/` stays on dash and is the console's root. The landing's stylesheet and fonts still answer on dash, because the maintenance page loads them there.
- **Crawlers.** dash's `/robots.txt` is `User-agent: *` / `Disallow: /`. teachouse.io keeps the landing build's robots file and sitemap.
- **Redirects** carry `Cache-Control: public, max-age=300`, so a browser holds one for five minutes. The host is read from `X-Forwarded-Host`, then `Host`, without its port and in any case. Any other host (a loopback health probe, a bare IP) gets the one-origin answer and is never redirected.

### Deploy

- `services.teachouse.landingHost = "teachouse.io"` and `services.teachouse.consoleHost = "dash.teachouse.io"`; the module asserts both or neither. `domain` stays `teachouse.io`.
- With `consoleHost` set, the module uses `https://dash.teachouse.io` as the identity service's `TAM_AUTH_BASE_URL`, tam-server's `--auth-issuer`, the default `server.mail.consoleUrl`, and adds it to the default `auth.trustedOrigins` beside `https://teachouse.io`. Option values you set yourself are not changed.
- DNS and the edge: `dash.teachouse.io` routes to the same origin as `teachouse.io`, with `/api/auth/*` going to the identity service on dash. On teachouse.io the edge should send `/api/auth/*` to tam-server so it gets its 301, not to the identity service.
- Signed-in sessions do not carry over: cookies are now set by dash only, so everyone signs in once on dash.
