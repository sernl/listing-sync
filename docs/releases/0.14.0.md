# Teachouse 0.14.0

## Tutorial

A new account is shown around the console the first time it signs in. The screen dims, one part of the console is lit at a time, and a card says what that part is for in one sentence, with Next, Back and Skip. The tour covers Import, Catalogue, New resource (what a resource is), Automate, Marketplaces (get the app, then connect), and Billing under Account. It ends on "Start here", whose button opens a new resource.

- The tour runs on a computer and on a phone. On a phone the card sits along the bottom edge, and it moves above the tab bar when the lit item is on the bar. Arrow keys step through it, Escape skips it, and Tab stays inside the card. With reduced motion turned on, the spotlight jumps from item to item without sliding.
- Completing or skipping the tour is saved to the user, and it is not offered again. **Show me around** on Help and guides starts it again from the first step.
- Accounts made before this release are not interrupted. They see the tour once, on their first visit after buying a plan, unless they have already completed or skipped it.
- An operator impersonating a user never sees the tour offered. If the operator starts it from Help, nothing is saved for the user.

### Under the hood

- Migration `0088_onboarding.sql` adds `app_user.tour_state` (`due` | `predates` | `completed` | `skipped`) and `tour_settled_at`. Existing rows become `predates` and new rows `due`.
- `GET /v1/profile` now includes `tour: { state, settled_at }`. `POST /v1/onboarding/tour` takes `{ "outcome": "completed" | "skipped" }`, records it at the server's time, and returns the profile.
- In the console, `web/src/lib/tour/` holds the step model, the rule that decides when to offer the tour, and the placement helper, plus `Tour.svelte`, which is a native modal `<dialog>`. Each step's element is found by its `data-tour` key.

### Upgrading

Server, then console. Run the migration before the server starts.
