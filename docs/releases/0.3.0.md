# Teachouse 0.3.0 for Windows and Android

This is the beta that follows 0.2.0.
It is still a beta, so expect rough edges, and please say what you find.
The headline is the console, redrawn end to end.
The console reaches browsers and existing installs the moment it is published, and 0.3.0 is the app build that carries the same console to Windows and Android.

## What you can do with it

The console is now three sections rather than one long list of pages.
Crosslist is your catalogue and everything you do to it: Resources, Labels, Import, Analytics, Template Manager and Export.
Automations is the scheduled work: Marketplace Sharing, Marketplace Migration and Marketplace Sync.
Marketplaces is where every marketplace lives — what is connected, what is not built yet, and where to get the app.
A narrow icon rail carries those three, and the section you are in opens its own list of pages beside it.
On a phone the rail becomes a four-tab bar along the bottom and the page list becomes a row of pills under the title, so the same console reads on a phone as on a desktop.
Every page says what it is in one line under its title, and every control that is switched off states why rather than leaving you to guess.

Resources is the home of the catalogue, and it now reads as a stack of cards rather than a table.
Each card carries the cover, the title, when it was last updated, the price and a chip for every marketplace, so a resource is one row and its marketplaces are visible without opening it.
Four tabs across the top count what is in each state — not listed, draft, listed, and needs you — and the last of those overlaps the other three deliberately, because a resource can be live on one marketplace and waiting on you at another.
The filter card searches by title and narrows by marketplace, by label and by standing.
Choosing a bulk action asks you to select the resources it applies to, then keeps a running count in a bar pinned to the foot of the page.
The actions offered are the ones that can actually run — cross-list, mark as listed, labels and delete — and anything that cannot run yet is shown switched off with its reason.
Nothing here delists and relists a listing to refresh it, and nothing will: that discards the reviews, the ratings, the sales history and the address a teaching resource has built up.

Labels is now a page of its own rather than a dialog.
It lists every label with the number of resources carrying it, and each row can be renamed or deleted.
A label comes into being the first time you put it on a resource and stops existing when the last resource lets it go, so the New label control explains that rather than opening a form that could not be accepted.
Deleting a label that is in use names the count first: it tells you it is on twelve resources before it removes it from all of them.
A label's colour is chosen from its name, so the same label looks the same everywhere it appears and there is nothing to pick.
A resource carries up to twenty labels, and the field says so rather than refusing after you press the button.

Import brings a shop across, with one card per marketplace.
Your own computer reads the shop under your own session and sends us a description of each resource — its title, its details and a small cover image.
The file a buyer downloads never leaves your machine.
Beneath that, every import you have run is listed newest first with the stage it reached, and an import still waiting for your computer to check in is listed there too rather than disappearing until it starts.
Each import has a page of its own showing the stage, the coverage it measured, and every listing it reached, with a skipped one carrying the reason it was given in the words it was given in.

Analytics keeps what a marketplace reported apart from what we counted ourselves.
Only TPT publishes figures, so sales, earnings and views come from TPT, and each carries the time it was captured.
TES publishes no statistics of its own, so its panel counts your own catalogue instead, and the page says which is which rather than mixing the two into one number.
There is no refresh button, because the read happens on your own computer on its own schedule and a button here would only look as though it were fetching.

Template Manager holds the answers you reuse, in two tabs.
Marketplace mapping is where you say how your own words for subject, topic, resource type and phase should be read at each marketplace.
Licence is never mapped for you: a licence has legal effect, so every marketplace's licence stays your own decision.
New resource is the second tab and it is now live: save a resource's details under a name, and the next resource of that kind starts filled in rather than blank.

Export gives you the catalogue as a spreadsheet.
One row per resource carrying its identifier, title, price, currency, labels and dates, then a status, a price and a link for each of TES GB, TES US, TES NZ, TPT and Etsy.
It is details only: no file a buyer downloads and no marketplace login is in it.
The file is built when you ask for it, so a large catalogue takes a moment.

Automations is three pages sharing one shape: your marketplaces down the left, and the selected marketplace's settings on the right.
None of the three carries a button that runs something now, and that is deliberate — the timer for TES and TPT lives on your own computer, so every page here schedules rather than starts.
Marketplace Migration moves a whole shop across once, with the source, the target and the TPT copyright declaration on one card and every past migration listed beneath it.
Marketplace Sync keeps each marketplace's copy of a resource agreeing with your catalogue, with the run list beneath it and the open questions reachable from its header.
Marketplace Sharing publishes one resource to every marketplace you are connected to on a schedule, and it is the one page here that is not built; see below.

Marketplaces is a new page, and the widest one.
TES and TPT lead the grid as the two you can connect today, each carrying the account it is signed in as, its status in one sentence, and a line saying where its work runs — on your own device, or on our servers under a token the marketplace issued us.
Behind them are nineteen more tiles.
Etsy and Shopify are marked coming soon, because both publish an official seller API and both would therefore run on our servers.
The other seventeen are marked as on our list, each saying in one clause where its work would run if it were built.
None of the nineteen is built, and no tile carries a date.
The grid closes with a card for asking us to support a marketplace we have not tiled: its name, its address, and what you sell there.
We read every one, and we cannot promise a date.
A line under the whole grid states that the marketplace names and logos belong to their owners, that Teachouse is not affiliated with or endorsed by them, and that they identify which marketplace each entry refers to and nothing more.

Beneath the grid the page carries a browser-extension section and a downloads section.
Neither extension exists yet, and the desktop app does everything an extension would.
Downloads is where the app comes from: Windows and Android each show the version and the SHA-256 checksum beside the button once a build is published, and Apple carries no button.
A card never links to a file that has not been published and verified, so a platform with nothing to offer says so rather than offering a link that fails.

Account keeps your preferences, your subscription, notifications, status and the guides, with the operator pages behind it for those who have them.
The subscription page carries the four tiers as they are priced and the state our payment provider reports.

## The new front page and the prices

Teachouse now has a public front page at the root of the site.
It describes what Teachouse does, how it works in three steps, what a subscription costs, what a migration costs, and the questions sellers ask, with a pricing page carrying those last three sections on their own.
The two pages read their figures from one source, so they cannot disagree about a price.
The site makes no third-party request at all: both fonts are served from our own origin, and there is no analytics script on it.
Signing in and signing up both lead to the console, and opening the desktop app sends you to the console rather than to the front page.

The prices are in US dollars.
There is a free tier, carrying one marketplace, twenty resources and manual sync.
Solo is $12 a month or $120 a year, and carries 100 resources kept in sync, two marketplaces, a daily sync, one computer and 50 resources migrated a year.
Studio is $24 a month or $240 a year, and carries 400 resources kept in sync, every marketplace, a sync every six hours, two computers and 200 resources migrated a year.
Publisher is $48 a month or $480 a year, and carries an uncapped catalogue kept in sync, every marketplace, an hourly sync, three computers and 500 resources migrated a year.
Studio carries a 14-day trial.

A migration — us moving your whole shop across once — is quoted before any work starts, at one of five fixed prices.
It is $49 for 50 resources or fewer, $79 for 51 to 100, $129 for 101 to 200, $199 for 201 to 500, and $299 for the first 500 plus $0.25 for each resource beyond 500.
Every migration includes 30 days of Studio, so you can look over the mappings on the listings we just created.
If you already subscribe, your plan's yearly allowance is used first and anything past it is half the band price.
Buy an annual plan within 30 days of a migration and the migration price comes off it in full.

## The emails, and the product mark

The emails Teachouse sends are now real messages rather than plain text.
Three go out, and they are the whole set: a welcome that confirms your email address, a password reset, and a notice whenever your password is changed, which is sent on every path that stores a new one.
Each carries the Teachouse mark, a greeting, one paragraph and a button, with the link printed underneath in full so the message still works when the button is stripped or images are blocked.
A plain-text version goes with every one, so nothing is lost to a reader that does not render HTML.
The link in an email is checked against our own address before it is sent, and your display name is cleaned and capped before it appears in a greeting.

Teachouse has a mark of its own now, a house with a book.
It is the browser tab icon on the web at every size a browser asks for, the application icon in the Windows app, the launcher icon on Android, and the image in the header of every email.
The 16-pixel version is drawn simpler than the rest, because the full mark does not survive that size.

## What changed in the app itself

The app itself changed in two places this release.

It carries the new product mark: the application icon in every size Windows uses, and an Android launcher icon with its own adaptive foreground.

The page the app shows when it cannot reach Teachouse has been redrawn to match the console.
It is bundled inside the app, so it loads with no network at all, and it carries a button that tries the connection again.

Nothing else in the app changed.
Your marketplace sign-ins, the schedule and every marketplace request work exactly as they did in 0.2.0, and they still run on your own computer.
The app shows you the console, and the work behind it is the app's own.

## What is not ready yet

Marketplace Sharing is the one Automations page whose settings do nothing.
It shows what sharing will do, every control on it is switched off with that reason stated, nothing on it is stored, and nothing on it reaches a marketplace.
Sharing runs on your own computer, so it arrives in a coming release of the app rather than with a console change.

Neither browser extension is available yet.
Chrome and Firefox are both marked coming soon, and the desktop app does everything an extension would.

There is no Apple build, and the Apple download card says so and carries no button.

Every marketplace except TES and TPT is a tile and nothing more.
Etsy and Shopify are marked coming soon, the other seventeen are marked as on our list, none is built, and no tile carries a date or implies a partnership.

Buying a subscription is not open.
The subscription page shows the tiers and the billing state, and says that billing opens soon and nothing on the page can be bought yet.

The privacy page and the terms page are placeholders, marked as drafts on the page itself, and both must be replaced before they mean anything.
The site publishes no contact address yet.

## Updates

If you are on 0.2.0, this arrives on its own.
The app checks the beta channel each time it opens and installs a new version before it starts working.

If you are on 0.1.3 or earlier, install this version by hand, once.
Those builds cannot fetch it themselves.
Download the installer below and run it over your existing installation.

The Android app does not update itself.
Download the new package and install it over the one you have.

The console needs no update at all.
It is served from Teachouse, so it is already what you see in a browser and what the app shows you when it opens, with nothing to install for it.

## Installing it

On Windows, download the `-setup.exe` installer and run it.
The `.msi` beside it installs the same application and exists for anyone who has to deploy it through Windows Installer.

Windows will warn you that the publisher is unknown.
That is expected for now: this build is not yet signed with a code-signing certificate, and the warning will go away in a later release.

On Android, download `Teachouse_0.3.0_arm64.apk`, which is built for 64-bit ARM devices.

The `SHA256SUMS.txt` file lists the checksum of each Windows installer, and `SHA256SUMS-android.txt` the checksum of the Android package, if you want to verify the download.
You can also get both builds from the console: the Marketplaces page has a Downloads section carrying each one with its version and its SHA-256 beside the button.

## For operators

`tam-server` takes two new optional flags.
`--landing-dir` points at the built landing site, which is read into memory once at start-up; the process refuses to start on a directory with no `index.html`, so a broken or empty build fails the process rather than serving a 404 at the root.
`--downloads-dir` points at the directory the downloads tier serves.
Absent either flag the server behaves exactly as it did before them.

One origin now answers four surfaces in a fixed order: the API's own routes, then the landing build, then `/downloads`, then the console.
The names `app`, `_app` and `downloads` are reserved ahead of the landing build whether or not the tier behind them is configured, so a landing build cannot quietly take a name the console needs.
The console's home moved to `/app`; its deep routes did not move.
The two document surfaces carry separate content-security policies, the landing page's being the narrower: no third-party host on any directive, no `unsafe-inline` on any, and `frame-ancestors 'none'`.

`teachouse-downloads-refresh` is a new oneshot on a fifteen-minute timer, running under its own account with the internet egress that `tam-server`'s own unit denies.
It fetches the current Windows installer from the update channel and the newest Android package and its checksums from GitHub with a read-only token, verifies every digest against the exact filename, stages under `.staging`, renames only what it verified into place, and writes `downloads.json` last.
A component it could not verify is left exactly as it was and the run ends non-zero, so a failed refresh never takes a working download away.
Without a GitHub token the Android half is absent rather than degraded.
A refresh that keeps failing is visible only in the journal and in `refreshed_at`, and nothing alerts on it.

Two migrations land with this release.
Migration 0055 creates `marketplace_request`: tenant data under row-level security, with the operator's cross-tenant read as an enumerated policy rather than a bypass, and its three text columns bounded at the column as well as at the route.
Migration 0056 creates `resource_template`, holding a named partial draft as `jsonb` under a type check and a byte ceiling.

The new API routes are:

- `GET /{version}/products/export` — the catalogue as CSV, read in set-based pages.
- `PATCH /{version}/labels/{name}` and `DELETE /{version}/labels/{name}` — rename and delete, one transaction each.
- `POST /{version}/marketplace-requests` — a seller's request, bounded per organisation.
- `GET /{version}/admin/marketplace-requests` — the operator's cursored read across tenants.
- `GET` and `POST /{version}/templates`, and `GET`, `PATCH` and `DELETE /{version}/templates/{template}` — the new-resource templates.

The downloads tier serves `/downloads/downloads.json` and `/downloads/<file>`, and is not an API route.
