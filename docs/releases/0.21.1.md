# Teachouse 0.21.1

Signing in stays up: the sign-in service's health check is no longer rate-limited, so the service is no longer restarted while it is healthy.

## Sign-in service

- **The health route is exempt from the rate limiter.** tam-auth's `GET /api/auth/ok` is now outside better-auth's limiter (`customRules: { '/ok': false }`, in the new `auth/src/rate-limit.ts`, which `auth.ts` imports). Kubernetes probes that route every few seconds with no `CF-Connecting-IP` or `X-Forwarded-For`, so every probe shared one no-client-address bucket. better-auth 1.7.2's database store restarts the window on each allowed request, so a steady probe stream climbed to the limit and stayed there, and the kubelet restarted healthy pods on `429`. On 2026-11-18 both replicas had restarted 22 and 34 times. `/ok` reads and writes nothing; every other path keeps the default rules, and sign-in is still throttled.
- `auth/src/rate-limit.test.ts` builds better-auth with exactly the production limiter: 250 probes in a row all answer `200`, the same burst without the exemption reaches `429`, and the fifth sign-in attempt in a row is still refused with `429`.

### Deploy

- No migrations and no configuration.
- With this tam-auth, the cluster's probes can go back from a TCP port check to `httpGet /api/auth/ok`.
