# Teachouse 0.20.0

## Site analytics

Admins can now see who visits the public site without a PostHog login: **Admin → Site analytics** (`/admin/analytics`, second in the admin menu).

- **What the page shows.** Pick 7, 30 or 90 days. Four figures head the page: visitors, page views, signups and conversion (signups per visitor), with Start free clicks under visitors. Below them are a line of visitors each day, then tables of top pages, referring sites (`$referring_domain`, "Direct or bookmarked" for `$direct`), UTM sources, countries and cities (`$geoip_country_name`, `$geoip_city_name`, top 20 each), and bars for device type, browser and operating system. A range is whole New Zealand days ending today, and a day with no visitors shows as zero. At 390 px the figures sit two across and every table becomes cards.
- **Where the figures come from.** `GET /v1/admin/analytics/site?range=7d|30d|90d` (operators only; `crates/tam-api/src/admin_analytics.rs`) sends eleven small HogQL queries to PostHog's query API (`POST {host}/api/projects/{id}/query/`), three at a time because PostHog runs at most three per project at once. It uses a personal API key as the bearer. Each query is named `teachouse admin site: …` so it can be found in PostHog's `query_log`. Pageviews are narrowed to `$host` = the `--landing-host`, because the console sends its pageviews to the same project. The answer is kept in memory for five minutes per range, and a failure is not kept. A refused key or a busy PostHog comes back as `502` with a sentence the page shows.
- **New events.** The landing's Start free and plan Choose links carry `data-cta` (`header`, `hero`, `closing`, `pricing-free`, `pricing-<price key>`). A click sends `cta_click` with `{cta}` by beacon, from the existing PostHog block in `Base.astro`. Signups are the server's existing `signup_completed`, which every sign-up path already sends (`session.rs`).
- **Configuration.** New `tam-server` flags: `--posthog-project-id <id>` and `--posthog-personal-key-file <path>`, given together or not at all, and `--posthog-api-host <url>`, which defaults to `https://eu.posthog.com`. That is the app host, not the ingestion host `--posthog-host`. Without them the route answers `503 "Site analytics is not configured"` and the page says so. NixOS module: `services.teachouse.server.siteAnalytics.{projectId, personalKeyFile, apiHost}`. A personal key drops tam-server's IP deny, as the mail relay key does, because PostHog is a name, not an address.
- **Deploy.** Create a PostHog personal API key with the **Query Read** scope, limited to the Teachouse project (PostHog → Settings → User → Personal API keys). Store it in safix as `teachouse-posthog-personal-key`. The project id is the number under PostHog → Settings → Project → General → "Project ID", and also the number in `https://eu.posthog.com/project/<id>/…`. It is not secret.
