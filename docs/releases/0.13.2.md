# Teachouse 0.13.2

The console survives a piece of itself failing to download, which is what the founder's phone actually met.

## What the phone's error was

The origin's own log answered the question 0.13.1 guessed at. The founder's Galaxy Note10+ runs a current System WebView (Chrome 153), so the missing-method fix in 0.13.1 was not his cause (it stands, for phones where it is). His session shows the shell running and then, on the next page, `/_app/version.json` asked for thirty times in a minute: that is SvelteKit checking for a new build after a chunk `import()` failed. The chunks that failed never reached the origin at all; on a fresh emulator the same page showed Cloudflare's 522, which is Cloudflare unable to open a connection to the origin. A page opens a dozen connections from a dozen Cloudflare edges at once, and after a deploy every chunk is a cache miss, so a burst of new inbound connections lands on the origin's uplink and some handshakes are dropped. The error page then showed "Internal Error", SvelteKit's default wording for the client, and nothing to press but a link to a page that needed the same chunks.

## What changes

- A chunk that fails to download reloads the console once (`hooks.client.ts`, `$lib/lost-chunk`), on every platform. The reload fetches the shell and chunks again over fresh connections, which is Vite's own guidance for its `vite:preloadError`. A second failure inside thirty seconds is shown instead: "Part of this page did not download, so it could not be drawn. Check your connection, then reload", with a Reload button.
- The error page shows the words a failure carried rather than "Internal Error", so the next one a seller reads out names its cause.

## What does not change here

The origin's inbound handshake loss is an infrastructure matter (moving the origin to an outbound-only Cloudflare Tunnel removes inbound connections altogether) and is decided in the fleet, not in this repository.

## Upgrading

Server, then app. The reload behaviour is served, so a phone that has the app draws it on its next open.
