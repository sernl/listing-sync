# Teachouse 0.21.0

## Distribute

- **Every platform from one tag.** `desktop-release.yml` now calls one reusable workflow per platform: Windows (NSIS + MSI, signed with Azure Artifact Signing or, failing that, a `WINDOWS_CERTIFICATE` PFX), macOS (one universal `.app` and `.dmg`, Developer ID signed, notarized and stapled), the Mac App Store (sandboxed `.pkg` uploaded to App Store Connect), Linux (AppImage + `.deb`) and Android (APK for sideload, AAB uploaded to Google Play's `internal` track). The Microsoft Store gets a signed offline installer and an automatic submission through the `msstore` CLI once the download mirror serves it.
- **A platform without its secrets is skipped, not half-built.** The verify job's "Release plan" table names what each platform needs and which secret is missing; the release job's table says what each platform job came to. Windows always builds, unsigned if no signing secret exists, because the installed base updates from it.
- **Updates on every desktop platform.** Every updater-capable file is signed (`.exe`, `.msi`, `.app.tar.gz`, `.AppImage`, `.deb`), uploaded to CrabNebula under its update platform, and `latest.json` carries `windows-x86_64`, `darwin-aarch64`, `darwin-x86_64`, `linux-x86_64` and the bundle-suffixed keys. Linux builds ask for updates by bundle type, so a `.deb` install is never handed the AppImage.
- **One `SHA256SUMS.txt`** per release replaces the per-platform sums files.
- **The download mirror reads the GitHub release for everything.** `downloads.json` is now schema 2: each platform has `version`, `updated`, `files` (kind, file, sha256, size) and a `store` link. Mac disk images, the MSI and the `.deb` are offered; the console's download cards put the reader's own device first; the landing's platform chips link each platform's download.
- **The Mac App Store build has no updater** (`--features app-store` on the desktop crate).

### Deploy

- NixOS: `services.teachouse.downloads.updateUrl` is removed (evaluation fails with a pointer if still set); `prerelease` now defaults to `true`; new `stores.{googlePlay,microsoftStore,macAppStore}`. The token file is still required while the repository is private.
- GitHub: the secrets and variables for each store are listed in `docs/notes/runbooks/release.md`. Nothing new is required for the next tag; each store starts the tag after its secrets are set.
