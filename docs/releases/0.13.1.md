# Teachouse 0.13.1

The Android app draws the console again on phones whose System WebView was never updated, and a resource's files behave after a change.

## Android: "That page could not be opened"

The app on a Galaxy Note10+ (Android 12) draws the console in the phone's own System WebView, which was Chrome 91. The console used two methods that engine lacks, `Object.hasOwn` and `Array.prototype.at`, and the first page to call one threw and was drawn as "That page could not be opened" with no cause named. The shell (`app.html`) now defines every such method before any module runs, on any engine that lacks it and on none that has it, and `polyfills.test.ts` holds that list against the source so a new use of a newer method fails the lane rather than a phone. The error page shows what the load threw, in small type, so a seller can read it out.

The same engine cannot run the create form's rules module at all: it does not know the `'wasm-unsafe-eval'` policy word, and it refuses a module built with reference types, which every module `wasm-bindgen` now emits. The server widens the policy to `'unsafe-eval'` for Chromium older than 97, and the form no longer depends on the module: where it fails to load, each verdict is asked of `POST /v1/authoring/check`, the function the module was compiled from, after the seller pauses typing. The old answer, "The form didn't load properly. Reload the page before you save", could never be got past on such a phone and is gone.

The remote console window also gets `notification:default`: the notification plugin's own page script asked for it on every load and was refused.

## A resource's files

- **Thumbnail after a replace.** The cover URL carries the cover's content hash (`/cover?v=<hash>`), so a changed thumbnail is a new URL and shows at once, and an unchanged one is cached for a year. A bare or stale URL is answered `no-cache`.
- **Previews you can inspect.** Each preview row offers View, Change, Rename and Remove. View opens the file in the console's viewer from the bytes on this machine; Change reopens the preview maker with the saved pages and watermark prefilled; Rename is inline, backed by a new `PATCH /v1/products/{product}/files/{file}` route that renames a file and nothing else (the thumbnail is refused, a synced file is not found). The maker shows the page it will make before you confirm.
- **The Files band** ends in one row: "What changes?" and "Add file", with room between them.

## Upgrading

Server, then app. The Android app needs no store update for the WebView fix: the console is served, so a phone that already shows the error page draws the console on its next open after the server is deployed.
