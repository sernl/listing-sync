# Teachouse 0.5.0 for Windows and Android

This is the beta that follows 0.4.0.
It is still a beta, so expect rough edges, and please say what you find.
Two things stand out: the app on Android opens on your console again, and you can copy or move resources from one marketplace to another with a preview of what will happen before anything does.
Under those, the phone's bottom bar is redrawn with New in the middle, and importing your shop a second time no longer creates what you already have.
Almost all of this reaches you from the server, so a browser has it the moment it is published, and 0.5.0 is the app build that carries the console's new start-up path to Windows and Android.

## What changed in the app

The app opens on your console.
On Android, 0.4.0 could open on a page saying "The console could not start. Internal Error (500)".
The cause was between your phone and Teachouse rather than in either: the service in front of Teachouse runs a check against automated visitors, that check needs a small script to run on every page, and our own page rules refused it, so a phone the check did not recognise was turned away on its first request.
The page rules now let that script run, on every platform, and the check has what it needs to recognise the app.
If the app still cannot reach Teachouse, it now says so in its own words, with the answer it actually got and a Try again, instead of the sentence above.

The theme is right from the first paint.
The script that reads your theme choice before the page draws had been refused since it was added, so a seller who chose Dark saw a flash of Cream before the console corrected itself; it runs now.

## What changed in the console

The phone's bottom bar has five cells, with New in the middle.
Import, Catalogue, New, Automate and Markets sit on equal cells, so New is at the exact centre of the screen and the two glyphs either side of it mirror each other.
The glyphs are larger, the labels are 12 pixels and none is cut short on a 360-pixel phone.
Search has moved to the top of the Resources page, beside your account picture, which is where Account has moved to as well; both are the same buttons they were, in a place that leaves the bar to navigation.
The search shortcut, Ctrl-K, is unchanged.

You can copy or move resources between marketplaces.
Migrations, under Automations, asks From and To, offers Copy or Move, and takes all of your resources on the source or a tick list of them.
Copy leaves the source listing where it is; Move drafts the listing on the target and removes it from the source once the target listing exists, never before.
Preview shows one row per resource before you confirm: Will create, Already there with a link to the listing, or Blocked with the reason.
A price carries across as the same number in the target's currency, and the row says so, so you can check it after it lands.
The confirm button names what it will do, Copy 3 resources or Move 3 resources, and how many moves your plan has left this month is on the page.
Each of Tes, TPT and Etsy can be chosen at either end; where a pair cannot be served yet the choice is disabled with the reason, so today the pair that runs is Tes to TPT.
On the Resources board, Copy or move is a bulk action that opens Migrations with your ticks already made.

A resource confirmed for a marketplace is not offered twice.
Until your device has sent it, the preview says it is already on its way rather than offering to create it again.

Every imported resource knows where it came from.
An import now records the listing each resource was read from, so the marketplace tiles on a resource show it as listed there, and Migrations can move it from there.
Reading the same shop a second time skips every listing you already have as the list lands, naming the resource it already is, and leaves only what the shop has gained to tick.

## What changed on the site

Nothing on the front page changed in this release.

## Known limitations

Migrations run from Tes to TPT.
TPT and Etsy cannot yet be a source, because Teachouse cannot download a resource's file from them; Etsy cannot yet be a target, because it is not connected to Teachouse.
Each of these is shown disabled with its reason rather than hidden.

A migration has been exercised end to end against the app's own tests and a live console; the listings it drafts on TPT are sent by your device the next time it checks in, and no seller's shop has yet been moved with it.

Copy and Move both count against your plan's monthly moves.

A resource imported from TPT is recorded as on TPT but without whether it is live or draft, since a TPT read does not carry that; it can be copied, and a Move from TPT waits on the file download in any case.

The check in front of Teachouse cannot be told to trust the app on the plan Teachouse is on.
If a phone is still turned away after this release, please tell us the time and the network you were on.

Email about a finished run is not yet being sent; the Notifications page and the device's own notification are where a finished run is announced.

Pressing back on Android with a picker or the search sheet open still moves you a screen rather than closing the sheet.

There is no browser extension for Chrome or Firefox, and no Apple build.
No marketplace beyond Tes and TPT is connected.
The privacy and terms pages are still drafts.

## Updating

If you are on 0.4.0 on Windows, this arrives on its own.
The app checks the beta channel each time it opens and installs a new version before it starts working.

The Android app does not update itself.
Download the package from this release and install it over the one you have.

The console needs no update at all.
It is served from Teachouse, so it is already what you see in a browser and what the app shows you when it opens, with nothing to install for it.

## Installing it

Windows will warn you that the publisher is unknown.
That is expected for now: this build is not yet signed with a code-signing certificate, and the warning will go away in a later release.

## For operators

No migration lands with this release.

Two routes land: `POST /{version}/migrations/plan`, which writes nothing, and `POST /{version}/migrations`, which writes a `sync_request` with every resource already canonicalised from the product's binding on the source and drains its own legs in the same handler.
The removal leg of a Move is gated on the target binding, as it always was.

Both content-security policies carry a fresh `'nonce-…'` on `script-src` for every HTML response, beside the hashes, which is what admits the edge's injected detection script; assets carry the policy as built.
The inline-script hash walk skips HTML comments; before this it took a `<script src>` mentioned in a comment for a tag and hashed the wrong bytes.

The download refresh reads a sums line written as `./NAME`; every release from v0.1.1 to v0.4.0 wrote them that way and the refresh had refused all of them.

The desktop client's window has navigated to `/app` since 0.4.0; nothing further changed in the client for this release beyond the version.
