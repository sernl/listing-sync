# M0 Tes spike implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove the full Tes draft write path from a server-side Rust client end to end — create a draft, upload a file via presigned S3, set metadata, read it back and diff, classify a deliberately interrupted write as ambiguous, and delete the throwaway — on the founder's own account, without ever publishing.

**Architecture:** A throwaway standalone Rust spike (`reqwest` + `tokio`) that drives the internal Tes JSON API discovered in M-1, authenticated by the founder's captured cookie jar. It is deliberately outside the gated workspace and follows the charter's spike rules: minimal ceremony, explicit timeouts, and record everything. Its surviving output is the fault taxonomy and the two endpoints M-1 could not capture (create-draft and delete), which promote into the production `tam-marketplace-tes` at M1.

**Tech Stack:** Rust 1.97.1, `reqwest` (async, rustls), `tokio`, `serde`/`serde_json`, `anyhow` for spike-grade errors.

## Deviation from the milestone document

`docs/design/milestones.md` M0 lists "the submission survives Tes's moderation gate and reaches the live state" as a green condition.
That requires publishing, which the founder has declined because a published resource goes live and can only be undone by deletion, and M-1 established that Tes drafts are a first-class non-live state.
This plan therefore proves the write path to a draft and defers the publish, moderation and live-state leg to a later supervised step on a resource the founder actually intends to publish.
Both milestone kill gates remain in force: whether a server-established session works, and whether an interrupted write classifies as ambiguous.

## Global constraints

- Rust 1.97.1; the spike is a standalone crate under `spikes/tes-spike/` and is not a member of the root workspace, so the gated lints do not apply to throwaway code.
- Account safety is paramount: every draft the spike creates carries the title prefix `ZZ-SPIKE-DELETE-ME`, no more than three exist at once, each is deleted in the same run that created it, and nothing is ever published.
- The spike never calls a publish endpoint; if one is discovered it is recorded and not invoked.
- Every HTTP request sets an explicit `.timeout()` and connect timeout; `reqwest` has no default timeout and a hanging spike teaches nothing.
- Record everything: every request and response, with headers redacted of cookie and signature values, appends to `probes/local/spike-<runid>.jsonl`, which is gitignored. The fault taxonomy is the spike's real deliverable.
- The cookie jar `probes/local/tes-cookies.jar` is a secret, gitignored, never printed or committed.
- Spike files carry `#![forbid(unsafe_code)]` and are `cargo fmt`-clean; no other enforcement applies.
- Endpoints confirmed in M-1 and used verbatim: `GET /api/tier/gmv/me`; `POST /api/v2/resources/{id}/draft` with JSON `{title, descriptionRaw, descriptionRawType:"md", categories:[{id}], ageRanges:[], ages:[], yearGroups:[], mainType, mainAge}`; `POST /api/resources/v3/draft/{id}/attachment` returning `s3pending.params`; a presigned `multipart/form-data` POST to the returned S3 URL; `GET /taxonomy/v4/{country}/{id}`. Create-draft and delete are discovered in Tasks 4 and 9.
- Commit recipe (jj colocated, signed): `jj describe -m "<msg>"`, then `jj bookmark set main -r @`, then `jj new`, then `git push origin main`.

```rust
#![forbid(unsafe_code)]
use anyhow::{Context, Result};
use std::time::Duration;

/// Build a Cookie header from the gitignored Netscape jar (fields: domain flag path secure expiry name value).
pub fn cookie_header(jar_path: &str) -> Result<String> {
    let text = std::fs::read_to_string(jar_path).with_context(|| format!("read {jar_path}"))?;
    let mut pairs = Vec::new();
    for line in text.lines() {
        let line = line.strip_prefix("#HttpOnly_").unwrap_or(line);
        if line.starts_with('#') || line.trim().is_empty() {
            continue;
        }
        let f: Vec<&str> = line.split('\t').collect();
        if f.len() >= 7 {
            pairs.push(format!("{}={}", f[5], f[6]));
        }
    }
    anyhow::ensure!(!pairs.is_empty(), "no cookies parsed from {jar_path}");
    Ok(pairs.join("; "))
}

pub fn client(cookie: &str) -> Result<reqwest::Client> {
    let mut headers = reqwest::header::HeaderMap::new();
    headers.insert(reqwest::header::COOKIE, reqwest::header::HeaderValue::from_str(cookie)?);
    headers.insert(reqwest::header::USER_AGENT, reqwest::header::HeaderValue::from_static("Mozilla/5.0"));
    reqwest::Client::builder()
        .default_headers(headers)
        .timeout(Duration::from_secs(30))
        .connect_timeout(Duration::from_secs(10))
        .build()
        .context("build client")
}
```

```rust
use anyhow::{bail, Result};
use reqwest::Client;

/// Discover create-draft. In M-1 the first draft write was POST /api/v2/resources/{id}/draft on an
/// existing id, so the id is minted earlier. Try the id-less create; record whichever candidate returns an id.
pub async fn create_draft(client: &Client) -> Result<i64> {
    let candidates = [
        ("POST", "https://www.tes.com/api/v2/resources"),
        ("POST", "https://www.tes.com/api/v2/resources/draft"),
        ("POST", "https://www.tes.com/api/resources/v3/draft"),
    ];
    for (_m, url) in candidates {
        let resp = client.post(url).json(&serde_json::json!({})).send().await?;
        let status = resp.status();
        let body: serde_json::Value = resp.json().await.unwrap_or(serde_json::Value::Null);
        if let Some(id) = body.get("id").and_then(|v| v.as_i64()) {
            println!("create-draft OK via {url} -> id={id}");
            return Ok(id);
        }
        println!("create-draft candidate {url} -> {status} (no id)");
    }
    bail!("no create-draft candidate returned an id; inspect the recorded responses")
}
```

```rust
#![forbid(unsafe_code)]
use anyhow::{Context, Result};
use reqwest::Client;

pub async fn upload_file(client: &Client, id: i64, path: &str) -> Result<()> {
    let name = std::path::Path::new(path).file_name().unwrap().to_string_lossy().to_string();
    let temp_id = "TEMP-SPIKE-0";
    // 1. request presign
    let presign: serde_json::Value = client
        .post(format!("https://www.tes.com/api/resources/v3/draft/{id}/attachment"))
        .json(&serde_json::json!([{"name": name, "tempId": temp_id, "previewOption": 0}]))
        .send().await?.error_for_status()?.json().await?;
    let params = presign[0]["s3pending"]["params"].clone();
    let s3_url = params["url"].as_str().or(params["action"].as_str())
        .context("no S3 url in presign params; inspect recorded response")?.to_string();
    // 2. multipart POST to S3 (fields from params, file last)
    let bytes = std::fs::read(path)?;
    let mut form = reqwest::multipart::Form::new();
    if let Some(fields) = params["fields"].as_object() {
        for (k, v) in fields {
            form = form.text(k.clone(), v.as_str().unwrap_or_default().to_string());
        }
    }
    form = form.part("file", reqwest::multipart::Part::bytes(bytes).file_name(name.clone()));
    let s3 = client.post(&s3_url).multipart(form).send().await?;
    anyhow::ensure!(s3.status().as_u16() == 204 || s3.status().is_success(), "S3 upload status {}", s3.status());
    // 3. confirm
    let confirm: serde_json::Value = client
        .post(format!("https://www.tes.com/api/resources/v3/draft/{id}/attachment"))
        .json(&serde_json::json!([{"type":"file","name":name,"tempId":temp_id,"id":presign[0]["id"],"order":1}]))
        .send().await?.error_for_status()?.json().await?;
    println!("attachment uploaded={}", confirm[0]["isUploaded"]);
    Ok(())
}
```

```rust
pub fn diff(expected: &serde_json::Value, actual: &serde_json::Value) -> Vec<String> {
    let mut out = Vec::new();
    if let Some(obj) = expected.as_object() {
        for (k, v) in obj {

                out.push(format!("{k}: expected {v}, got {}", actual.get(k).cloned().unwrap_or(serde_json::Value::Null)));
            }
        }
    }

}
```

```rust
#![forbid(unsafe_code)]

#[derive(Debug, PartialEq, Eq)]
pub enum WriteOutcome {
    Committed,
    Failed(String),
    Ambiguous(String),
}

/// Positive-assertion classification of a write response.
/// A write is Committed only if the body is JSON carrying the expected resource id.
/// Anything that could mean the write did or did not land is Ambiguous.
pub fn classify(status: u16, body_text: &str, expected_id: i64) -> WriteOutcome {
    let looks_signin = body_text.contains("<html") && (body_text.contains("sign-in") || body_text.contains("login"));
    match status {
        200 | 201 => match serde_json::from_str::<serde_json::Value>(body_text) {
            Ok(v) if v.get("id").and_then(|x| x.as_i64()) == Some(expected_id) => WriteOutcome::Committed,
            Ok(_) => WriteOutcome::Ambiguous("200 JSON without the expected id".into()),
            Err(_) if looks_signin => WriteOutcome::Ambiguous("200 but a sign-in interstitial".into()),
            Err(_) => WriteOutcome::Ambiguous("200 but body is not the expected JSON".into()),
        },
        401 | 403 => WriteOutcome::Ambiguous(format!("{status}: auth challenge, write state unknown")),
        429 => WriteOutcome::Ambiguous("429: rate limited, write state unknown".into()),
        408 | 502 | 503 | 504 => WriteOutcome::Ambiguous(format!("{status}: transient, write state unknown")),
        400 | 404 | 422 => WriteOutcome::Failed(format!("{status}: definitively rejected")),
        _ => WriteOutcome::Ambiguous(format!("{status}: unclassified")),
    }
}

#[cfg(test)]
mod tests {
    use super::*;
    const ID: i64 = 42;
    #[test] fn committed_needs_the_expected_id() {
        assert_eq!(classify(200, r#"{"id":42}"#, ID), WriteOutcome::Committed);
    }
    #[test] fn truncated_body_is_ambiguous() {
        assert_eq!(classify(200, r#"{"id"#, ID), WriteOutcome::Ambiguous("200 but body is not the expected JSON".into()));
    }
    #[test] fn signin_interstitial_is_ambiguous() {
        assert!(matches!(classify(200, "<html>please sign-in</html>", ID), WriteOutcome::Ambiguous(_)));
    }
    #[test] fn rate_limit_is_ambiguous() {
        assert!(matches!(classify(429, "", ID), WriteOutcome::Ambiguous(_)));
    }
    #[test] fn auth_challenge_is_ambiguous() {
        assert!(matches!(classify(403, "", ID), WriteOutcome::Ambiguous(_)));
    }
    #[test] fn hard_reject_is_failed() {
        assert!(matches!(classify(422, "", ID), WriteOutcome::Failed(_)));
    }
    #[test] fn wrong_id_is_ambiguous_not_committed() {
        assert!(matches!(classify(200, r#"{"id":99}"#, ID), WriteOutcome::Ambiguous(_)));
    }
}
```
